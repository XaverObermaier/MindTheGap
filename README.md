# Mind the Gap

An AI-assisted platform making global inequality, humanitarian crises and development issues easier to understand — and turning awareness into action. See [PROJECT.md](PROJECT.md) for the full mission, SDG alignment, and project background.

## Live site

**https://xaverobermaier.github.io/MindTheGap/**

(Only live once GitHub Pages is enabled for this repo — see below.)

## Running it locally

This is a plain HTML/CSS/JS site (no build step), but it uses ES modules and `fetch()` to load shared partials and JSON data. Browsers block that over a `file://` URL, so **you can't just double-click `index.html`** — it needs to be served over `http://`.

Easiest option, from the project root:

```bash
python -m http.server 5500
```

Then open `http://localhost:5500/index.html`.

No Python? VS Code's **Live Server** extension does the same thing — right-click `index.html` → "Open with Live Server".


## Data pipeline

`data/countries.json` is generated by [`pipeline/fetch_worldbank_data.py`](pipeline/fetch_worldbank_data.py), not written by hand. It pulls four indicators — population, Gini index, poverty headcount ratio at $3.00/day, and prevalence of undernourishment — live from the [World Bank Open Data API](https://data.worldbank.org/) (no key required) for the site's five countries (Sudan, Kenya, Yemen, Haiti, Nigeria), then merges them with a small set of hand-curated, cited figures:

- **Current crisis estimates** — how many people are affected by the specific crisis described on each country's page right now, e.g. Sudan's 19.5M facing severe food insecurity (UN News, Sept 2026) or Haiti's 1.5M internally displaced (IOM, June 2026). This drives the map's colour-coded need level.
- **Nigeria's National MPI** — 63% of Nigerians classed as multidimensionally poor, from Nigeria's National Bureau of Statistics 2022 report, added at the project's request since NBS doesn't expose this through a public API.

Every one of those manual figures ships with a source link and a "checked as of" date in `pipeline/fetch_worldbank_data.py`, and shows up as a citation on the site itself (see each country's "Current crisis" and "Structural indicators" boxes).

**Why need level isn't computed from the live World Bank numbers:** for a country in active conflict, the last real household survey is often a decade old — Sudan's and Yemen's poverty figures below are both from before their current wars. Using those stale numbers to colour the map would show the world's most severe crises as *low* need. So `needIndex` is instead computed from the cited current-crisis figures, and the World Bank numbers are shown separately as "structural indicators" so the gap between the two stays visible instead of getting averaged away. `html/about.html` explains this to site visitors.

**Re-running it:**

```bash
cd pipeline
pip install requests   # stdlib urllib is actually used, so this is optional
python3 fetch_worldbank_data.py
```

This overwrites `data/countries.json` with fresh World Bank numbers (same curated crisis figures, until you update `CRISIS_ESTIMATES` in the script by hand). It needs unrestricted internet access to `api.worldbank.org` — it will fail with a 403/connection error in network-locked environments (it did in the sandbox this was built in; ran fine from there via the assistant's own web-fetch tool, which is how the current `data/countries.json` was actually populated — see `pipeline/_seed_from_session_fetch.py` for exactly which live API responses were used).

**News data** (`data/news.json`) isn't pipeline-generated yet. We tried: ReliefWeb's and HDX's API endpoints both returned HTTP 403 to every automated request made while building this, even simple documented ones, which looks like bot/edge protection rather than a wrong request — their regular web pages loaded fine, just not `api.reliefweb.int` or the HDX API. The `try_fetch_reliefweb()` function in the pipeline script is a stub for whoever gets that working. Until then, the five items in `data/news.json` are real, dated, individually verified and cited news from UN News, WFP, and FEWS NET — not automated, but not placeholder either.

## Deploying / enabling GitHub Pages

1. Push the current work to `main` on GitHub.
2. In the repo on GitHub: **Settings → Pages → Source → Deploy from a branch → `main` / `(root)`** → Save.
3. GitHub will publish the site at `https://xaverobermaier.github.io/MindTheGap/` within a minute or two.

No further setup needed — the site was built to work correctly whether it's served from a domain root or from a GitHub Pages project subpath like this one.
